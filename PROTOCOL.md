# Remote Control — Wire Protocol (v1)

Shared contract between the Android "Remote" app and the Windows "Host" service.
Both sides MUST implement exactly this. If either side needs to deviate, stop and
flag it rather than silently diverging — the other side depends on this contract.

## Transport

- WebSocket, plain `ws://` (no TLS — LAN-only, out of scope for v1).
- Windows Host listens on `0.0.0.0:8765` (port configurable but 8765 is the default
  used everywhere: QR payload, UI, docs).
- Path is irrelevant — Host accepts the upgrade on any path (use `/` from the client).
- One JSON object per WebSocket text frame. No newline framing, no batching.
- Encoding: UTF-8 JSON, object per message, `type` field always present.

## Pairing / discovery payload (QR code)

The Host encodes this JSON as the QR code content (Settings/Pairing screen):

```json
{ "v": 1, "ip": "192.168.1.24", "port": 8765, "token": "k7Q-3f9a", "name": "MATT-XPS" }
```

The Android app scans it, stores `ip`, `port`, `token`, `name` locally, and connects to
`ws://<ip>:<port>/`.

## Auth handshake

Immediately after the WebSocket opens, the client MUST send:

```json
{ "type": "auth", "token": "k7Q-3f9a" }
```

Host responds with one of:

```json
{ "type": "auth_ok", "name": "MATT-XPS" }
{ "type": "auth_error", "message": "invalid token" }
```

If the client doesn't send `auth` as the first message, or sends a wrong token, or the
connection originates outside the Host's local subnet, the Host closes the socket
(WebSocket close code 4001) without processing anything else. No other message type is
accepted before `auth_ok`.

## Client → Host messages

```json
{ "type": "volume", "action": "set", "value": 45 }        // value: 0-100
{ "type": "volume", "action": "mute" }                     // toggles mute
{ "type": "volume", "action": "get" }                      // request current state

{ "type": "brightness", "action": "set", "value": 70 }     // value: 0-100
{ "type": "brightness", "action": "get" }

{ "type": "media", "action": "play_pause" }
{ "type": "media", "action": "next" }
{ "type": "media", "action": "previous" }
{ "type": "media", "action": "seek_forward" }               // best-effort, see README
{ "type": "media", "action": "seek_back" }                  // best-effort, see README

{ "type": "app", "action": "launch", "id": "spotify" }      // id from the apps list

{ "type": "apps", "action": "list" }                        // request configured shortcuts

{ "type": "ping" }
```

## Host → Client messages

```json
{ "type": "auth_ok", "name": "MATT-XPS" }
{ "type": "auth_error", "message": "invalid token" }

{ "type": "ack", "for": "volume" }
{ "type": "ack", "for": "brightness" }
{ "type": "ack", "for": "media" }
{ "type": "ack", "for": "app" }

{ "type": "error", "message": "unauthorized" }
{ "type": "error", "message": "app not found: spotify" }
{ "type": "error", "message": "unsupported action" }

// Pushed proactively whenever volume/brightness/mute changes, from ANY source
// (phone command, or the user moving the physical slider on the laptop) —
// this is how the phone slider stays in sync with real OS state.
{ "type": "state", "key": "volume", "value": 45, "muted": false }
{ "type": "state", "key": "brightness", "value": 70 }

// Sent once right after auth_ok, and again whenever the shortcut list changes
// (added/removed in the Host UI) so the phone's Apps tab stays current.
{ "type": "apps", "items": [
  { "id": "browser", "name": "Browser", "tag": "BR" },
  { "id": "music",   "name": "Music",   "tag": "MU" }
] }

{ "type": "pong" }
```

## Field notes

- `id` for an app is a slug derived from its configured name (lowercase, non-alnum
  stripped) — generated by the Host when the shortcut is added, stable until removed.
- `tag` is a 2-letter uppercase label the Host derives from the name, used as the
  fallback tile glyph on the phone (no icon extraction in v1).
- All numeric `value` fields are integers 0-100 inclusive.
- Unknown `type` → Host replies `{"type":"error","message":"unsupported action"}` and
  keeps the connection open.

## Reconnection

- Client is expected to retry with backoff (start ~2s, cap ~10s) whenever the socket
  closes or fails to open, and re-send `auth` immediately on every new connection —
  the Host does not remember clients across connections.
- Host has no notion of "the same phone reconnecting" — every connection re-authenticates
  from scratch. Only one client is supported at a time in v1; a new authenticated
  connection replaces the previous one (Host closes the old socket).

## Security

- Host rejects (before even reading `auth`) any TCP connection whose remote address is
  not in the same IPv4 subnet as the Host's active adapter (mask comparison, not just
  "same /24 guess").
- Token is regenerated only when the user clicks "Rotate token" in the Host UI —
  otherwise stable across Host restarts (persisted to disk).
